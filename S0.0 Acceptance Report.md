# S0.0 Acceptance Report — Integration Contract and Scaffolding

Status: Accepted  
Date: 2026-08-12  
Authoritative plan: [`S0 Integration Design.md`](S0%20Integration%20Design.md)

## Scope

S0.0 freezes the responsibility and dependency rules for the Integrated S0
milestone. It deliberately adds no `ServerRuntime`, host loop, UI runtime,
Accounting, Inventory, Network, or other later-slice feature.

The design document remains the normative contract. This report records the
repository audit and validation evidence for accepting that contract as the
first slice.

## Ownership map

| Boundary | Current or reserved ownership | Dependency rule |
| --- | --- | --- |
| Kernel | `Kernels/ECS`; `Kernels/ECS.Generators` | Engine-agnostic mechanisms only. No dependency on Server, Game, Client, Host, Godot, or Network. |
| Runtime / bridges | `Server/Runtime` and `Server/Hosting` are reserved for S0.1/S0.2; existing `Server/Persistence` remains the persistence bridge | May depend on kernels and explicit persistence contracts. Must not own game policy, UI workflow, domain databases, or host-specific presentation. |
| Game composition | `Game/Composition`, `Game/Simulation`, `Game/Admission`, `Game/Accounting`, `Game/Inventory`, and `Game/UI` are reserved for later slices | Owns the actual game policy and domain state. It may compose lower layers; lower layers must not depend on it. |
| Client / renderer | `Client/Core` and `Client/_Godot` are reserved for S0.4 | Client Core owns neutral client behavior and the local semantic endpoint. The renderer owns presentation and must not mutate authoritative server state. |
| Authoring / tooling | `Scripts` and `Tools/UiDesigner` are reserved for later work | Produces definitions/content for composition; it does not become runtime authority. |
| Tests / benchmarks | `_Tests` and `_Benchmarks` | Validate product boundaries and performance. They are not runtime dependencies or ownership layers. |

`_V2` remains a behavioral and design reference only; it is not part of the
new dependency graph.

## Frozen dependency direction

The accepted direction is:

```text
Authoring / Mods (later)
            |
            v
Game Composition (later)
            |
            v
Runtime / Bridges -----> Kernels
            ^
            |
Hosts / Renderers (platform edges)
```

More specifically:

- Kernels do not reference Runtime, Game, Client, Hosting, Godot, or Network.
- Runtime and bridges translate, route, and synchronize; they do not become a
  second gameplay or UI authority.
- Hosts instantiate and drive the common runtime through explicit typed startup
  capabilities. They do not subclass it into divergent server semantics or
  publish participant roots independently.
- Game composition supplies policy above Runtime. `ServerRuntime` is not a
  service locator or a V2-style application facade.
- Client Core communicates through the future `LocalSemanticLink`; it does not
  share live ECS storage or call gameplay objects directly.
- Renderers depend on client-facing contracts and engine controls, never on
  server-owned ECS state.

## Frozen S0.0 contracts

- `ServerRuntime` is the only authoritative server runtime concept.
- `ServerGeneration` is the single active authority root; future publication is
  one root ownership transfer.
- `LocalSemanticLink` is the local client/server path; packet networking is
  deferred.
- UI definition, model, and action are separate concepts; normal prepared UI
  routing is typed/numeric rather than handwritten runtime strings.
- Accounting is optional admission/domain state.
- S0 inventory truth is game-owned ECS state; any index is derived and
  reconstructible.
- The listed S0 non-goals remain deferred, including Network V3, production
  authentication, Gump Maker, a generalized Inventory kernel, and physics
  injection.

## Validation evidence

The existing suites were run without changing their sources or project
references:

```text
dotnet run --project _Tests/UltraSim.ECS.Tests/UltraSim.ECS.Tests.csproj -c Release
  All 218 ECS Next runtime/primitive tests passed.

dotnet run --project _Tests/UltraSim.ECS.Generator.Tests/UltraSim.ECS.Generator.Tests.csproj -c Release
  All 28 ECS generator tests passed.

dotnet run --project _Tests/UltraSim.Server.Persistence.Tests/UltraSim.Server.Persistence.Tests.csproj -c Release
  All save-set transaction tests passed.
```

No new runtime feature was added to satisfy the design. The current active
tree therefore contains only the accepted ECS kernel and persistence bridge;
future ownership directories remain reserved rather than represented by empty
projects.

## Exit gate

S0.0 is accepted because a proposed file or type can be assigned to exactly one
of Kernel, Runtime/Bridge, Game Composition, Client/Renderer/Host, or
Authoring/Tooling using the map above and the authoritative plan. S0.1 is the
next slice and must introduce the first runtime code only within the frozen
boundaries.
