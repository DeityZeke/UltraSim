# UltraSim S0.8 Hardened Acceptance Report

Status: Accepted after adversarial correction

Date: 2026-08-14

Workload: `ultrasim-s0.8-integrated-acceptance-v3`

Kernel baseline: ECS 3.4.1

## Executive result

Integrated S0 is accepted with the generation-coherence defects found by the
independent audit corrected. One concrete engine-neutral game composition runs
through InternalHost and HeadlessHost with real generated ECS scheduler work,
account-backed and accountless admission, cached semantic UI, inventory
mutation, three-participant durable persistence, derived-index rebuild, and one
atomic whole-game generation replacement.

The authoritative generation is now explicitly:

```text
ECS world + persistent world clock + complete game state
```

A save made at simulation tick 12 was allowed to diverge to tick 19, then
restored to tick 12 and its exact saved world-time fraction. A fresh
HeadlessHost loaded the same tick, time, ECS, Accounting, and Inventory state.
Playback rate remained policy of each loading host and was not smuggled into
the save.

The cadence-independence follow-up also makes simulation frequency host policy:
the complete save set now round-trips 60 -> 20 and 20 -> 60 Hz while preserving
exact nonzero fractional world time. The loading host keeps its configured
frequency, and optional live cadence changes are disabled by default. Full
contract and evidence are in
[`Authoritative Cadence Independence Report.md`](Authoritative%20Cadence%20Independence%20Report.md).

## Corrections made after the original S0.8 audit

### Generation and runtime authority

- Added a strict `clock` save-set participant for simulation tick, world-time
  rate, integer time, and a fixed frequency-independent fractional quantum.
- Restore now prepares ECS, Accounting, clock, derived Inventory, and the game
  aggregate outside every callback borrowing the old generation.
- ECS scheduler tick and restored clock tick must agree before publication.
- Runtime has explicit game-callback, simulation, publication, and
  publication-notification operation states. Lifecycle/publication reentrancy
  is rejected before mutation.
- Publication observers may perform one callback-scoped reconciliation against
  the new root. They cannot stop, dispose, tick, republish, or nest authority.
- A borrowed root is checked unchanged/live at callback exit. Callback failures
  are terminal only while Runtime is still running; they cannot turn an already
  disposed runtime into a contradictory `Faulted` state.

### Persistence ownership and durability

- Save is split into owner-thread immutable capture and detached durable
  publication. `TrySaveAsync` releases authority before encoding, hashing,
  flushing, renaming, and publishing `CURRENT`.
- Artifacts are hashed while written rather than reread from disk.
- Captured state is owned and disposed on every preflight/publication failure.
- Prepared publication is exactly-once: a failed callback cannot retry.
- Staged identity namespaces cannot fall through to an old active-world
  resolver. External resolution requires an explicit immutable-external
  capability.
- The coordinator uses its filesystem abstraction for discovery, metadata,
  locking, reads, writes, cleanup, and promotion.
- Durable directory flush is implemented for Windows, Linux, and macOS.
- Malformed `CURRENT`, null manifest artifacts, sequence disagreement,
  concurrent writers, stale pending work, and crash points have adversarial
  coverage with narrowly classified recovery.
- The legacy ECS+Accounting-only publisher is internal and available only to
  its historical regression test assembly.

### Admission and presentation

- Account-backed sessions retain durable controlled identity and trusted
  identity, reauthorize on Play, and atomically rebind after generation
  publication.
- Accountless sessions have no durable authorization record and are explicitly
  invalidated on replacement.
- Expected game rejection remains a result inside the trusted callback.
  Exceptions escaping that boundary remain terminal and are never converted
  into an ordinary Inventory rejection.
- Authority commits before presentation delivery. If a post-commit UI update
  or close fails, the mutation/entry remains committed and the UI session is
  detached/resnapshot-required with an isolated presentation fault.
- Each open view binds one authoritative action handler. Observer ordering can
  no longer change whether authority executes.

### UI and Inventory hardening

- Renderer-neutral open/update/close/delta/action protocol types moved from
  `Client/Core` into neutral `Kernels/UI`; game policy no longer depends on the
  client assembly.
- Row actions carry source-element provenance and must name an existing row in
  the current model of that exact source list.
- Godot applies flow spacing/sizing/alignment and style roles; display-only
  text/toggle controls are native read-only. Unsupported fixed flow sizing is
  rejected rather than silently rendered as content sizing.
- Client list patches are grouped by compact slot and clone each affected list
  once; unchanged immutable rows are structurally shared. Godot uses prepared
  slot/action adjacency instead of rescanning the definition.
- UI definition/view families, dynamic text, row counts, and row-cell counts
  are explicitly bounded. Malformed UTF-16 is rejected before canonical hashing.
- Inventory's packed child-node index remains because the 100K mostly-empty
  container test justifies shared actual-use storage. Its physical node index is
  internal, and a deterministic 5,000-operation property test covers donor-link
  repair against ECS truth.
- Inventory item/container policy has one cold authoring source used for both
  prefab components and bound content metadata.

## End-to-end acceptance gate

The account-backed scenario proves:

1. InternalHost starts the ordinary Runtime and concrete game composition.
2. Alice, durable Accounting linkage, Backpack, Bread x5, and Iron Sword are
   created through normal public game/ECS APIs.
3. CharacterSelect opens cold, validates row provenance, and enters Alice.
4. Inventory opens cold; Split emits exactly `Update + Add` and Equip emits
   exactly `Remove`, with no full-list replacement.
5. Twelve hosted ticks advance both ECS scheduler tick and authoritative clock.
6. One common epoch captures `world + accounting + clock`; durable publication
   continues after authority is released.
7. Live state diverges through entity/content mutation, seven more ticks, and a
   changed host playback rate.
8. Load prepares and validates the complete candidate privately, rebuilds
   Inventory, and publishes one generation root outside the old lease.
9. Old runtime handles are stale; persistent identities resolve to new runtime
   entities with the saved state.
10. Runtime tick/time return to the saved values while host playback remains the
    current host's policy.
11. Existing account-backed admission rebinds to the restored entity; an
    accountless session is explicitly invalidated.
12. CharacterSelect and Inventory reopen through exact cached hot paths.
13. A fresh HeadlessHost loads the same generation and matches the complete
    normalized generation hash.

The native Godot 4.7.1 Mono gate uses the exact production CharacterSelect and
Inventory definitions. It verifies cached reopen, granular list reconciliation,
layout/style semantics, display-only controls, source provenance, and native
root preservation.

## Deliberate boundaries

- Trusted game callbacks are a capability contract, not a memory-safe language
  sandbox. They must not retain the supplied world/game objects. Runtime now
  enforces the important machine invariants around reentrancy, publication, root
  stability, and disposal.
- Synchronous `TrySave` remains available when a caller explicitly accepts full
  durable latency on its thread. Hosted use should prefer `TrySaveAsync`.
- Durable-ID assignment is monotonic. A failed save may leave unused IDs; it
  never reuses externally observable durable identity merely to eliminate gaps.
- Persistence remains a cold path with proportional immutable snapshots and
  staged restore ownership. Further copy reduction requires profiling, not a
  weakened transactional boundary.
- This milestone is local semantic integration, not Network V3, terrain,
  physics, or a production-complete inventory/account/UI feature set.

## Validation

Acceptance requires:

- all engine-neutral ECS, generator, persistence, runtime, hosting, UI, client,
  Accounting/Admission/Inventory, and S0 executable suites;
- Debug and Release builds with zero warnings;
- Godot 4.7.1 Mono S0.4 and S0.8 headless native acceptance;
- canonical InternalHost/HeadlessHost parity and saved clock assertions;
- zero warmed tick allocation and the 5% paired wrapper gates;
- `git diff --check`.

S0.8 cadence hardening adds no ECS runtime kernel API and does not advance ECS
3.4.1; only scheduler time/cadence XML documentation was clarified.

## Verdict

S0 is accepted after hardening. The audit found real integration defects, but
not a reason to redesign ECS V3. The corrected foundation now treats generation
replacement, durable time, authority, presentation, admission, UI protocol, and
recovery as one coherent system contract. New feature work can build on this
boundary without carrying the original S0.8 clock and lifetime omissions.
