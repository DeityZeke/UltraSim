# UltraSim S0.8 Acceptance Report

Status: Accepted  
Date: 2026-08-13  
Workload: `ultrasim-s0.8-integrated-acceptance-v1`  
Kernel baseline: ECS 3.4.1

## Executive result

Integrated S0 is complete. One concrete engine-neutral game composition now
runs through InternalHost and HeadlessHost with real generated ECS scheduler
work, account-backed and accountless admission, cached semantic UI, inventory
mutation, transactional ECS + Accounting persistence, derived-index rebuild,
and atomic whole-game generation replacement.

The accepted account-backed run saved, deliberately diverged, and restored the
world. The InternalHost restore and a fresh HeadlessHost load produced the same
canonical logical hash:

`BB02C6DABFE3290EA4DA7F4443E60F2B0370707927A8B0318A69DB4C99D9927A`

Old runtime entity handles did not resolve after publication. Alice, Backpack,
Bread stacks, equipped Sword, prefab provenance, persistent identities,
Accounting linkage, simulation state, and derived Inventory counts all matched
the accepted save state.

## Delivered implementation

- `GameSimulationSystemRuntime` and `GameSimulationJob` provide the minimal
  deterministic scheduled simulation used by every game world shape.
- `UltraSimGameComposition` registers the same system and lookup for fresh,
  hosted, and persistence-staging worlds.
- `GameGenerationState` exposes callback-scoped reads of its minimal simulation
  state without exposing or retaining an alternate world authority.
- `_Tests/UltraSim.S0.Integration.Tests` owns the full deterministic semantic,
  persistence, hosting, cache, allocation, and canonical gates.
- `_Tests/UltraSim.S0.Godot.Tests` renders the exact CharacterSelect/Inventory
  definitions with the real `GodotUiRenderer`; its game dependencies are
  deliberately test-only.
- Accepted Split projection now treats an impossible post-proof projection
  failure as a terminal invariant failure instead of silently publishing a
  successful status without row deltas.
- `RuntimeAccountingPersistence` is explicitly hidden compatibility evidence;
  `GameRuntimePersistence` is the forward whole-game path.

## End-to-end account-backed gate

The accepted test proves:

1. InternalHost starts the ordinary ServerRuntime and concrete composition.
2. Alice, her durable Accounting record, Backpack, Bread x5, and Iron Sword are
   created through normal public game/ECS APIs.
3. CharacterSelect is initially absent from cache, opens cold, renders Alice,
   and routes Play back through the semantic link.
4. Inventory opens cold and projects Bread/Sword.
5. Split emits exactly `Update + Add`; Equip emits exactly `Remove`; neither
   emits `Replace`.
6. Twelve hosted ticks advance `GameSimulationState.TickMarker` through the
   registered generated chunk system.
7. SaveSetCoordinator commits one two-participant `world + accounting`
   generation.
8. Live state then diverges by destroying restored fixture items, creating an
   Apple, and ticking seven additional steps.
9. Load prepares ECS and Accounting privately, resolves durable references,
   rebuilds Inventory, validates, and publishes one GameGenerationState.
10. Old Alice/Backpack handles are stale; restored entities have new runtime
    identities but the same persistent IDs.
11. CharacterSelect and Inventory reopen through their exact cached hot paths.
12. A fresh HeadlessHost loads the same accepted generation and matches the
    InternalHost normalized hash.

## Accountless gate

Accountless admission directly creates a playable character, runs four real
scheduled ticks, and round-trips through the composition's declared save set.
The Accounting store contains zero accounts and zero characters before and
after restore. The empty Accounting artifact remains part of this concrete
composition's persistence declaration; it is not required for normal
accountless admission or simulation.

## Native Godot gate

Godot 4.7.1 Mono headless acceptance passed with the actual Admission and
Inventory workflows driving the exact production definitions. It verified:

- native CharacterSelect shows Alice;
- exact cached hot reopen succeeds;
- native Inventory shows Bread and Iron Sword;
- Split `Update + Add` reconciles rows without replacing the root;

The test lives in a separate Godot test project so `Client/_Godot` remains an
engine adapter and does not gain server/game composition references.

## Residual seams, explicitly not hidden

- Shared UI semantic operations currently live physically under Client/Core.
  Before Network V3 freezes packaging/wire contracts, evaluate moving shared
  types into a neutral contracts assembly. This is packaging debt, not an
  Inventory authority defect.
- The S0.6-only `RuntimeAccountingPersistence` remains for historical tests.
  New composition work must use `GameRuntimePersistence`; delete the old bridge
  when S0.6 fixture preservation no longer requires it.
- Runtime WorldClock is not a third save-set participant in S0.8. ECS scheduler
  tick/system state and game component state restore; the currently running
  host clock retains its explicit runtime publication semantics. A future host
  policy that needs clock rewind must add an honest participant rather than
  smuggling clock state into ECS or Accounting.
- This is local semantic integration, not Network V3, physics, terrain, or a
  production inventory feature set.

## Verdict

S0.8 is accepted. UltraSim now has a small but real coherent engine runtime,
not merely independently benchmarked subsystems. The next major integration
pressure should attach Network V3 to the proven runtime, admission, durable
identity, lifecycle, persistence, and semantic UI seams.
