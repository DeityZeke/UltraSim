# S0.3 Acceptance Report — UI-0 Definition and Compiler Kernel

Status: Accepted after independent adversarial review and repair

Date: 2026-08-13

Profile: `integration-s0.3-ui-definition-compiler`

Authoritative plan: [`S0 Integration Design.md`](S0%20Integration%20Design.md)

## Objective and scope

S0.3 adds the renderer-neutral UI-0 substrate: readable cold authoring,
deterministic immutable compilation, prepared numeric bindings,
definition-bounded model tables/list counts, and transient action validation.
It intentionally stops before
client caching, LocalSemanticLink, Network, Godot controls, JSON transport, and
game-specific widgets.

## Accepted contract

- `UiDefinitionKey` identifies an authoring family; version, canonical
  `UiDefinitionHash`, and the 128-bit `UiDefinitionHandle` identify one exact
  compiled revision. A stale revision cannot route an action into a changed
  definition merely because its reusable key is unchanged.
- Cold `UiDefinitionBuilder` scopes provide Canvas, Vertical, Horizontal,
  Overlay, and Scroll containment plus Panel, Text, Image, Button, TextInput,
  Toggle, and List elements.
- `UiDefinitionCompiler` flattens lexical authoring into immutable numeric
  layout/element/slot/action tables. Layouts and elements retain one shared
  sibling ordinal so interleaved flow order remains reconstructible. Source-key
  lookup is retained only in the cold `UiPreparedBindings`
  diagnostic/preparation surface.
- Slot/action declarations return definition-local `UiSlotReference` and
  `UiActionReference` values. Normal game code can author bindings and prepare
  numeric runtime IDs without repeating string keys; cross-definition
  references reject.
- Slot and action IDs are numeric and declaration-order stable. Binding typos,
  duplicate declarations, typed slot mismatches, invalid containment, and
  unsupported configuration values reject explicitly.
- Canvas children require logical rect placement with normalized anchors/pivot
  and z-order; flow children reject Canvas placement. Compiler validation does
  not trust constructor-only validation. Depth, compiled node/element,
  declaration, source-text, and list-row limits bound accepted definitions and
  models.
- `UiModel` owns only dynamic scalar values, list row snapshots, and action
  availability/reason state. It validates values and action requests against
  the retained definition and never participates in definition hashing.
- `UiListRow` and replacement snapshots clone caller data; duplicate/invalid row
  IDs and excessive row counts reject.
- Action contracts statically declare row-context and input-kind requirements;
  `UiActionRequest` carries transient view, exact definition, action, row,
  typed input, and sequence identity.

## Independent-review corrections

The initial 10-test implementation built cleanly, but it was not accepted as
submitted. Review reproduced and repaired these contract failures:

- handles were derived only from `UiDefinitionKey`, so old and changed layouts
  shared an action-routing identity;
- normal authoring still required handwritten slot/action strings despite the
  typed/prepared-ID exit gate;
- layout nodes and elements used separate child lists without a common sibling
  order, losing meaningful interleaving inside flow layouts;
- TextInput/Toggle intent had no typed input contract and action input was not
  validated;
- equivalent `+0`/`-0` layouts hashed differently, and anchor ordering was not
  validated;
- compiler guards relied too heavily on public constructors and accepted an
  internally supplied zero-sized Canvas;
- failed authoring callbacks left partially attached root/child state;
- `Any` slots could retain scalar and row state simultaneously;
- definition keys had no length ceiling even though other source keys did.

The repair retained renderer independence and did not add client, transport,
Godot, game-widget, or runtime execution behavior.

Scalar text length and list-row cell-count transport ceilings are intentionally
not invented here. S0.3 models are server/local state; S0.4 patch framing and
any later remote transport must impose their own byte/value limits before
materializing untrusted dynamic payloads.

## Test evidence

The focused suite passes 19 tests in both Debug and Release covering:

- prepared numeric IDs and complete S0 vocabulary compilation;
- model values, list rows, action reasons, and action availability remaining
  outside the definition hash;
- layout changes changing the hash and equivalent source compiling
  deterministically;
- unknown/typo bindings, duplicate slot/action declarations, and typed binding
  mismatches rejecting;
- invalid Canvas/flow containment and depth/count/text limits rejecting;
- unsupported layout/element kinds rejecting safely;
- bounded row replacement, duplicate row detection, and stale definition/action
  request rejection;
- definition-local typed references and cross-definition misuse;
- typed action inputs and interactive binding mismatch rejection;
- canonical signed-zero hashing and invalid anchor geometry;
- independent compiler validation of injected source state;
- transactional retry after failed root/child authoring callbacks;
- one active state shape for `Any` slots;
- mixed layout/element sibling-order preservation.

Accepted command:

```text
dotnet run --project _Tests/UltraSim.UI.Tests/UltraSim.UI.Tests.csproj -c Release
```

The UI project also builds independently without warnings in Debug and Release.
The suite is renderer-neutral and does not claim S0.4 client or Godot behavior.

## Exit gate

A readable server-owned UI definition now compiles once into a bounded immutable
renderer-neutral representation and is populated through typed numeric model
and action state without stringly runtime routing. S0.4 may add the client
runtime, local semantic link, cache, and minimal Godot renderer.
