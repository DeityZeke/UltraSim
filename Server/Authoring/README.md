# Server-owned C# Scripts authoring — P2

`UltraSim.Server.Authoring` is a cold server-side adapter over BCL-only `Framework.RuntimeHost`. It uses Roslyn 4.5 / C# 11 to compile trusted ordinary C# under an explicitly selected server-owned `Scripts/` root. `Framework.RuntimeHost` does not reference Roslyn. This is executable server-author code, **not a security sandbox**; no downloaded/untrusted code is admitted by this path. AssemblyLoadContext fences dependency identity/lifetime but does not make author code safe.

Source layout is `Scripts/<canonical-package-id>/manifest.json` plus `*.cs` files at the package root or in canonical subdirectories such as `Items/Weapons.cs`. The package directory must exactly match the manifest ID. Discovery sorts ordinally, rejects case conflicts, non-source files and reparse/symlink paths, and bounds composition count to 128, source files and directories to 64/package each, source-directory depth to 4, relative path length to 384, source bytes to 256 KiB/package and 2 MiB/composition. Only the explicit manifest and C# source enter compilation. Canonical relative source paths affect the compile key; absolute source paths do not.

`UltraSim.RuntimePackage/v4` describes Contracts → Core → Scripts stages, half-open dependency version ranges, package capability relationships, separately declared live service relationships, direct terminal package-ID aliases, and optional durable-schema participant ownership. `entrypoint` is a canonical fully qualified public parameterless type implementing `IRuntimePackageLifecycle`; it is optional for vocabulary-only packages. The planner rejects backward stage edges, duplicates, absent required relations and cycles before compilation. Built-in and compiled entrypoints use the same RuntimePackageHost lifecycle and generation fences.

Compilation references only admitted BCL runtime assemblies, three canonical host contract assemblies (RuntimeHost, Persistence, ControlPlane), and selected outputs reached by declared package/capability/service relations. One composition load context resolves those host contracts to the default canonical assemblies and selected compiled images to exactly one admitted identity. It rejects other assembly resolution; this is deterministic dependency admission, **not** a malicious-code barrier. Arbitrary hot unload/reload and proven collectible reclamation are not claimed.

The exact SHA-256 `CompileKey` covers manifest bytes, ordered relative paths/source hashes, package version, compiled dependency identities, admitted reference hashes, compiler/language/options profile and relevant runtime architecture. It excludes timestamps, absolute paths and process-local generation. A privately staged cache entry is published only after successful emit, with a metadata/hash/managed-PE/assembly-name check on reuse. An incomplete or corrupt entry recompiles. The resolved `RuntimeCompositionFingerprint` includes manifest plan identity and every admitted compiled identity; it is not the manifest-only fingerprint or host Generation.

The sample under [Server/Scripts.Sample](../Scripts.Sample/) contains a Contracts-only package, an optional Core with a runtime service, a package-owned Control Plane provider and a non-ECS Framework save-set participant, plus a Scripts consumer that survives Core removal. A required-Core consumer fails planning before authority. The Core declares its durable participant in the manifest; `ServerScriptComposition.SaveParticipants` includes the package-schema ledger and all declared participants. Reopening a save after Core removal, identity rename or schema version change fails closed, even when an alias resolves the package name. Package aliases do not transform durable artifacts; an explicit migration/drop operation would be needed, and is not silently invented by P2. The real Direct Connect server accepts `--scripts-root=<path>` and optional `--scripts-cache=<path>`; it starts this composition **before** constructing Concept Demo authority/Network. This opt-in P2 seam does not yet alter Concept Demo game semantics or install dynamic hooks/facets into that Game. Startup diagnostics identify package/source/line/column and failures return nonzero without starting authority. No compiler/cache/file polling runs during authority ticks.

Focused gate: `dotnet run --project _Tests/UltraSim.Server.Authoring.Tests/UltraSim.Server.Authoring.Tests.csproj -c Release`. The gate covers cold/warm cache, source invalidation, Contracts-only survival, source/compile/admission failures, startup rollback, explicit Control Plane retirement, a non-ECS save-set participant and warmed direct-service allocations.
