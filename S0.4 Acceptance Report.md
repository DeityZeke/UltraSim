# S0.4 Acceptance Report — Local Client UI Runtime and Minimal Godot Renderer

Status: Accepted after independent adversarial review, repair, measurement, and native Godot execution

Date: 2026-08-13

Profile: `integration-s0.4-local-client-ui`

Authoritative plan: [`S0 Integration Design.md`](S0%20Integration%20Design.md)

## Review of prior slices

The S0.1–S0.3 reports and current implementation were reviewed before this
slice:

- S0.1 keeps `ServerRuntime` and `ServerGeneration` authoritative and does not
  expose mutable generation roots to a client.
- S0.2 keeps host wrappers at the lifecycle/tick edge and supplies no client,
  transport, service locator, or concurrent authority seam.
- S0.3 provides exact compiled definition handles/hashes, definition-local
  typed references, immutable topology, dynamic `UiModel` state, bounded rows,
  and typed transient actions. It remains renderer-neutral.

Those boundaries are preserved. S0.4 references `Kernels/UI` from client code,
does not reference Server/Runtime or Server/Hosting, and does not add Network,
JSON, packet, socket, or server-authority mutation behavior.

## Objective and scope

S0.4 proves local server-driven Gump behavior with an exact definition cache,
open-view registry, model deltas, typed local actions, and a small Godot
renderer. The client core is engine-neutral and independently testable; the
Godot project contains all renderer-specific controls.

## Accepted contract

- `UiDefinitionCacheKey` includes server identity, composition identity,
  protocol, definition key/version, and exact definition hash. A hot open
  requires an exact cache hit.
- Cold open validates the definition/model pair, caches the compiled definition,
  creates a view instance, and invokes the renderer once. Hot open reuses the
  cached immutable definition and creates only a new instance.
- Definition-family supersession is version-monotonic. A newer exact revision
  closes old instances, evicts the old cache entry, and may replace the same
  instance ID. Downgrades and different hashes reusing one version reject
  before closing the current view or invoking the renderer.
- `UiModelDelta` carries a definition handle, sequence, scalar slot patches,
  list replace/add/update/remove patches, and action-state patches. Multiple
  distinct row patches may target one list atomically. Duplicate row targets,
  replace-plus-row ambiguity, scalar/list aliasing, and typed slot mismatches
  reject before model cloning or renderer publication.
- Updates reject stale/duplicate sequence numbers and mismatched definitions.
  Operations and deltas own immutable snapshots. Model cloning shares immutable
  list snapshots until a list is changed, so scalar updates do not deep-copy
  every list row. Patches apply to a candidate model before renderer
  publication, so ordinary validation failure changes neither state.
- `LocalSemanticLink` exposes only logical OpenView, UpdateView, CloseView, and
  SubmitAction operations. It performs no packet encoding, JSON serialization,
  socket I/O, or authority mutation.
- The runtime is owner-thread-bound. Client action submission validates the
  open instance, exact definition, action contract, row context, typed input,
  and dynamic availability before emitting a `UiActionRequest` through an
  explicitly attached authority endpoint. Closed instance IDs retire and
  cannot be reused into an action ABA.
- Renderers receive `UiModelView`, a read-only capability rather than mutable
  `UiModel`. An unexpected Create/Apply/Close exception terminally faults the
  client runtime because native control state may have been partially changed;
  a failed Apply never publishes the candidate model or sequence. Renderer
  action callbacks are post-render capabilities; synchronous callback reentry
  during Create/Apply/Close is rejected and faults the renderer transaction.
- Godot maps Canvas/Vertical/Horizontal/Overlay/Scroll to Control,
  VBoxContainer, HBoxContainer, layered Control, and ScrollContainer; elements
  map to Panel, Label, TextureRect, Button, LineEdit, CheckBox, and a bounded
  VBox row list. Scalar patches update existing controls. List add/update/remove
  patches update only the affected row; replace rebuilds the list by contract.
- List definitions may bind an explicit row-context action; native row input
  submits the row ID and respects dynamic action availability. Overlay children
  receive shared bounds, Scroll retains padding, and changed row cell counts
  reconcile the existing row control.
- Godot controls and asset resolution are confined to `Client/_Godot`; no
  Godot type appears in `Kernels/UI` or `Client/Core`.

## Independent-review corrections

Luna's initial six tests and process smoke passed, but the implementation was
not accepted as submitted. Review reproduced or established these gaps:

- a cold open could downgrade a definition family or replace a different hash
  under the same version;
- same-instance supersession was rejected even though definition replacement
  is a normal server-driven operation;
- one delta could not update two different rows in the same list;
- public operation/model/delta surfaces exposed mutable backing state and the
  renderer received the mutable client model;
- scalar updates deep-cloned all list rows;
- the runtime had no owner-thread or terminal renderer-fault policy;
- closed requested instance IDs could be reused, allowing stale action ABA;
- List had no renderer-routable row action while a Button could incorrectly
  bind a row-context action it could never satisfy;
- Godot row updates left surplus cell controls, Overlay shared bounds and
  Scroll padding were incomplete, and disabled row actions could still emit;
- a missing local authority subscriber silently discarded otherwise valid
  action intent;
- a renderer could synchronously submit action intent during model publication
  against the previous client state;
- there was no executable Godot semantic test or required S0.4 performance
  baseline.

## Test and smoke evidence

The focused client suite passes 18 tests covering:

- cold/hot exact-cache behavior;
- definition-family supersession and stale hot-open rejection;
- existing-view scalar/list/action patching without a second control-tree
  creation;
- sequence rejection and atomic model preservation after failed validation;
- list replace/add/update/remove semantics;
- typed action delivery through `LocalSemanticLink` without mutating the source
  model;
- monotonic/exact supersession and same-instance replacement;
- multi-row list transactions and conflicting target rejection;
- operation/delta snapshot ownership and read-only renderer capabilities;
- owner-thread enforcement and renderer terminal-fault behavior;
- rejection of renderer action callback reentry during model publication;
- definition-bound delta validation and cache-identity bounds;
- closed-instance ABA prevention and missing authority endpoints;
- repeatable cold/hot/scalar/list performance and allocation rows.

## Performance baseline

The permanent engine-neutral baseline uses a no-op memory renderer and times
only the client-runtime operation; operation construction and cleanup are
outside the timed region. Fixed-JIT, 31-sample repeated processes produced:

| Operation | Representative mean | p95 | Managed allocation/op |
| --- | ---: | ---: | ---: |
| cold open/cache insert | 623 ns | 673 ns | 1,176 B |
| exact-cache hot open | 334 ns | 390 ns | 542 B |
| scalar delta | 186 ns | 213 ns | 328 B |
| one list-row update | 462 ns | 483 ns | 880 B |

Three fresh processes measured approximately 615–652 ns cold, 328–337 ns hot,
184–192 ns scalar, and 451–487 ns list-row mean. These are local regression
guards, not cross-machine claims and not Godot control-construction timings.
The nonzero allocations are deliberate bounded snapshot/view state costs; S0.4
does not claim ECS-style zero-allocation UI mutation.

## Explicit non-goals

Network transport, packet/document encoding, JSON, sockets, remote admission,
server authority mutation, production asset catalogs, rich styling, and domain
widgets remain later work. Any remote transport must impose explicit
artifact/message/value/count limits before materializing untrusted definitions
or dynamic payloads; S0.4 accepts only trusted in-process semantic operations.

## Exit gate

The same S0.3 compiled definition/model/action semantics now operate through a
local client cache, hot/cold view registry, live scalar/list/action deltas, and
native Godot controls. The renderer creates the tree once, patches existing
targets, and routes local input as typed action intent. S0.5 may add admission
and optional Accounting.
