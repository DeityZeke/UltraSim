# S0.2 Acceptance Report — Hosts and Minimal Platform Capabilities

Status: Accepted after independent review

Date: 2026-08-13

Profile: `integration-s0.2-hosts`

Authoritative plan: [`S0 Integration Design.md`](S0%20Integration%20Design.md)

## Objective and scope

S0.2 proves that hosting remains outside the authoritative server runtime. Both
wrappers construct and drive the same concrete `ServerRuntime`; neither subclasses
it or introduces divergent simulation behavior.

This slice does not add UI, Network, Accounting, Inventory, persistence
composition, physics, service location, reflection-based capability lookup, or
additional speculative platform abstractions.

## Accepted contract

- `InternalHost` drives the ordinary runtime in-process through semantic
  lifecycle/fixed/elapsed tick calls. It creates no fake packet or socket loopback.
- `HeadlessHost` drives the same runtime and provides bounded deterministic
  `RunFixedSteps` plus idempotent process-facing `Shutdown`.
- `Shutdown` is cleanup-safe before start, after stop, after a fault, and when
  repeated. The ordinary `Stop` and drive APIs preserve Runtime's lifecycle
  rejections rather than silently accepting invalid state.
- Hosts preserve Runtime's single-owner thread contract; they do not add locks,
  concurrent tick authority, or participant races around the authoritative root.
- Both wrappers expose only lifecycle, fixed/elapsed tick control, playback, and
  bounded generation/tick/time status. They cannot publish or replace generation
  roots.
- `HostCapabilities` is a typed cold value containing only the optional
  `IHostLogSink` actually consumed by S0.2. There is no `IServiceProvider`,
  reflection lookup, arbitrary capability map, or fake future dependency.
- Headless hosting defaults to a basic console sink. Internal hosting has no
  implicit output sink; either wrapper may receive an explicit sink.
- Diagnostics are best-effort and non-authoritative. Ordinary sink failures
  cannot change start/stop/disposal or simulation behavior. Catastrophic memory
  exhaustion is intentionally not hidden.
- Cancellation stops `RunFixedSteps` between complete simulation steps and does
  not implicitly shut the runtime down. Driving—even a zero-step/cancelled
  request—requires an already running runtime.

## Findings corrected during review

Luna's core hosting shape was appropriately small, but three acceptance gaps were
fixed:

1. The disposal test depended on a new `InternalsVisibleTo` grant into Runtime and
   inspected the internal generation/world directly. That grant was removed. The
   test now proves real ECS disposal through the registered system runtime's
   exactly-once `Shutdown` observation.
2. A throwing optional log sink could make `Start`, `Stop`, or `Dispose` report
   failure after authoritative state had already changed. Diagnostic emission is
   now failure-isolated and has an adversarial throwing-sink regression.
3. No host-specific allocation or wrapper-cost evidence existed. The suite now
   verifies zero warmed allocation for `InternalHost.Tick` and
   `HeadlessHost.RunFixedSteps`, and runs a 21-sample alternating direct-runtime
   versus InternalHost control.

Lifecycle coverage was also strengthened so zero-step runs cannot bypass the
running-state requirement, while process `Shutdown` remains cleanup-idempotent.

## Test and measurement evidence

The focused suite passes 11 tests covering:

- independent instances of the same concrete `ServerRuntime`;
- host lifecycle parity and cleanup-safe shutdown;
- foreign-thread rejection without changing live host state;
- identical generation/tick/world-time and scheduled fixture output;
- cancellation without implicit shutdown;
- ECS scheduler/system shutdown exactly once;
- ordinary and throwing logging sinks not changing simulation/lifecycle state;
- valid absence of InternalHost logging;
- zero warmed managed allocation through both host drive paths;
- repeated alternating wrapper timing with canonical work equality.

Accepted measurement command:

```text
DOTNET_TieredCompilation=0 DOTNET_ReadyToRun=0 \
dotnet run --project _Tests/UltraSim.Server.Hosting.Tests/UltraSim.Server.Hosting.Tests.csproj -c Release
```

Representative reviewed row:

```text
samples=21 ticks_per_sample=2000
direct ServerRuntime mean/p95 = 218,600 / 228,100 ns
InternalHost mean/p95 = 225,695 / 260,400 ns
wrapper ratio = 1.032
delta = 3.55 ns/tick
```

This is a local minimal-fixture regression guard, not a cross-machine claim. Five
additional fresh fixed-JIT processes produced wrapper ratios from 1.014 to 1.043
(about 1.6–4.6 ns/tick). Both warmed drive paths allocated zero caller-thread
managed bytes.

The unchanged 218-test ECS suite, scheduler/lifecycle/content/persistence tests,
28 generator tests, save-set transaction tests, and all 13 S0.1 tests also pass.

## Exit gate

Internal and headless execution now host one concrete authoritative runtime with
equivalent deterministic results. Startup, typed optional diagnostics,
fixed/elapsed driving, cancellation, and graceful cleanup live at the host edge;
simulation and generation authority remain in Runtime/ECS. A later host can use
the same documented public runtime controls without subclassing or modifying the
authoritative machine. S0.3 may now add only the UI-0 definition/compiler kernel.
