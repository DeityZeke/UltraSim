## Product and ownership

- `ServerOperatorService` is the owner-thread seam for Save Now, autosave, Backup Now, Shutdown, restart-with-save and exact-session Kick. `ServerOperatorProvider` publishes typed, capability-checked Control Plane actions; console, exported Godot GUI and a trusted local/test generic Admin viewer invoke that same provider. Accepted and rejected requests use the bounded Control Plane audit. A separate 256-entry operator event ring records bounded operational status without becoming Game history.
- The exported GUI is a separate Godot process. Its packaged ServerOnly headless child has no Godot dependency. Inherited bounded stdio frames reach the child's Control Plane adapter on the owner thread; there is no unauthenticated management listener or frontend-owned persistence path. The GUI owns its scene nodes, retires them across two `ProcessFrame` boundaries and verifies strong-reference native retirement in the physical smoke.
- The participant collection joins the existing sanitized Game monitor projection with the exact current control-session epoch and public actor identity. It reports no invented Account/Character identity or private coordinates. The fixed-rate Concept Demo exposes playback as read-only **disabled**, not as a mutable or cold setting; Pause is not fabricated.
- The GUI's Recovery Candidates view hashes bounded published backups in a separate read-only maintenance process. Confirmed selected restore first completes ordinary graceful server shutdown, then invokes the existing exclusive-lease, hash-validated cold restore. That staged Game restore publishes a **new forward live generation** before the GUI reopens the same deployment. A missing/corrupt selection is rejected while the previous live generation remains reopenable. The GUI cannot close midway through the bounded maintenance invocation.
- The exported `run-managed.sh` interprets only restart exit code 75 as a cold process relaunch. Server identity/configuration/save root are retained; sessions, runtime generation and dense handles are recreated. EOF from an unexpectedly lost GUI parent requests the same graceful Shutdown from the headless child.

The remotely authorized in-game Admin route is deliberately **unavailable**. No durable Account or trusted session-bound operator grant is selected yet, so player-supplied roles/names cannot publish a `ControlPrincipal`. The generic Admin viewer was exercised with a trusted local/test principal and demonstrated the same audited Save action and confirmation-gated Shutdown as console/GUI. F4 remains the sanitized read-only Game monitor. This is the explicit P7 identity-bound limitation permitted by the mission, not a claim that remote Admin is complete; a future trusted grant/management transport needs its own security decision.
